# v0.6.3 验收标准

日期：2026-10-20 · 版本：V1

## 1. 功能验收

### AC-1 请求级退避可配置（对应 R1）

- [ ] 不配置任何键时，连续失败的重试间隔为 `3, 10, 30, 60, 120, 120…` 秒
- [ ] 服务端返回 `retry-after` 时以响应头为准；超过 `max_retry_after`（默认 60 s）则放弃该次请求
- [ ] 模型配置 `advancedOverrides` 写入 `retry_schedule: [1, 5, 15]` 后，间隔变为 `1, 5, 15, 15…`
- [ ] `retry_schedule` 写错（空数组、负数、字符串）时**回退默认阶梯**，会话能正常启动、不抛异常

### AC-2 轮次级等待重发（对应 R2）

- [ ] 请求级重试耗尽后，不再立刻 `should_exit`，而是等待后重发整轮
- [ ] 等待间隔为 `10, 30, 60, 120, 300` 秒逐次加宽，默认最多 6 次
- [ ] 等待期间对话界面出现 `[Info] 上游错误，Ns 后轮次级重试 (n/6)...` 进度行
- [ ] 用户点"停止"后 **0.5 秒内**退出，不再发出新请求
- [ ] 一次真实工具调用成功后计数器归零（不发生跨任务累积）
- [ ] 无错误的任务行为与改动前**完全一致**（不新增等待、不新增输出）

### AC-3 Goal Mode 完成驱动（对应 R3）

- [ ] state 文件写入 `completion_signal` 且 `turns_used >= 2` 时，`check()` 返回 `/exit`，状态置 `done_completed`
- [ ] `turns_used < 2` 时忽略信号，继续正常唤醒
- [ ] 未写 `completion_signal` 时行为与改动前一致，预算耗尽仍按 `wrapping_up` 收口
- [ ] continuation prompt 含完成协议与 state 文件路径，且不再出现"无法宣告完成"
