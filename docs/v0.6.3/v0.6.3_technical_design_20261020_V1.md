# v0.6.3 技术方案 — 对话中断治理

日期：2026-10-20 · 版本：V1 · 对应 PRD：[v0.6.3_prd_20261020_V1.md](./v0.6.3_prd_20261020_V1.md)

## 1. 设计结论（先给结论）

三个需求全部落在 **managed GA payload 的一处 patch**（`1000-managed-interruption-resilience.patch`），不改 GUI、不改 Rust、不改 IPC 协议。原因是中断发生在引擎内部的两层重试上，而 Galley 已经通过 patch 栈拥有这两层的所有权。

| 需求 | 落点 | 改动量 |
|---|---|---|
| R1 请求级退避可配置 | `managed-ga/code/llmcore.py` `_stream_with_retry._delay` + `BaseSession.__init__` | +13 / +3 行 |
| R2 轮次级等待重发 | `managed-ga/code/ga.py` `_retry_or_exit` + 4 个调用点；`agent_loop.py` 工具分发 | 重写 1 个方法 |
| R3 Goal Mode 完成驱动 | `managed-ga/code/reflect/goal_mode.py` `check()` + `CONTINUATION_PROMPT` | +17 行 |

## 2. 现状与问题定位

### 2.1 请求级重试（R1）

`llmcore._stream_with_retry` 内部有一个闭包 `_delay(resp, attempt)`，原实现：

```python
return None if ra and ra > cap else max(0.5, ra or min(30.0, 3.0 * (2 ** attempt)))
```

两个硬伤：

1. 上限 `min(30.0, ...)` 写死 —— 第 3 次以后退避不再增长，长时间 5xx 必然打穿。
2. 曲线不可配置 —— 用户无法按自己网络状况调整。

`retry-after` 响应头优先的语义是正确的，保留。

### 2.2 轮次级重试（R2）

`ga.py` 的 `GenericAgentHandler._retry_or_exit(prompt)` 是"这一轮模型输出不可用"时的兜底：空响应、流异常、工具格式错误、max_tokens。原实现累计 3 次后 `should_exit=True` 直接结束会话，**中间没有任何等待**——这就是用户看到"干几步就断"的直接原因：上游抖动 20 秒，三次重试在 1 秒内全部打空。

### 2.3 Goal Mode（R3）

`reflect/goal_mode.py` 的 `check()` 只按 `budget_seconds` 收口；`CONTINUATION_PROMPT` 原文明确写"无法宣告完成"，模型即使做完了也只能继续空转直到预算耗尽。

## 3. 详细设计

### 3.1 R1：分级退避阶梯

新增模块级常量与归一化函数：

```python
_DEFAULT_RETRY_SCHEDULE = [3, 10, 30, 60, 120]

def _normalize_retry_schedule(value):
    """请求级退避阶梯（秒）。任何不可用取值都表示"用默认"。"""
    if not isinstance(value, (list, tuple)) or not value: return None
    tiers = []
    for item in value:
        try: sec = float(item)
        except (TypeError, ValueError): return None
        if sec <= 0: return None
        tiers.append(sec)
    return tiers
```

`_delay` 改为：

```python
if ra and ra > cap: return None
if ra: return max(0.5, ra)
schedule = getattr(sess, 'retry_schedule', None) or _DEFAULT_RETRY_SCHEDULE
return max(0.5, float(schedule[min(attempt, len(schedule) - 1)]))
```

设计取舍：

- **归一化失败即回退默认**，不抛异常。配置错误不应该让会话起不来。
- **阶梯用尽后停在末档**（`min(attempt, len-1)`），不无限增长，避免用户等十分钟。
- **`retry-after` 仍然优先**，但超过 `max_retry_after` 仍然放弃（保留原有防呆，避免服务端给一个荒谬值把会话挂死）。
- `0.5` 秒地板保留原语义。

`BaseSession.__init__` 新增：

```python
self.retry_schedule = _normalize_retry_schedule(cfg.get('retry_schedule'))
try: self.turn_retry_max = max(1, int(cfg.get('turn_retry_max') or 6))
except (TypeError, ValueError): self.turn_retry_max = 6
```

两个键都从模型配置 `cfg` 读取，因此**默认值生效时不需要任何配置**。

### 3.2 R2：轮次级等待重发

`_retry_or_exit` 从普通函数改为生成器（调用点本来就是 `try_call_generator`，天然支持）：

```python
def _retry_or_exit(self, prompt):
    '''轮次级重试：请求级重试耗尽后，退避等待再重发整轮，而不是直接收工。
    上限来自模型配置 turn_retry_max（默认 6）；用户中途停止立刻放弃等待。'''
    self._empty_ct = getattr(self, '_empty_ct', 0) + 1
    sess = self._llm_session()
    max_turn_retries = max(1, int(getattr(sess, 'turn_retry_max', 6) or 6))
    if self._empty_ct >= max_turn_retries: return StepOutcome({}, should_exit=True)
    backoff = [10, 30, 60, 120, 300]
    d = backoff[min(self._empty_ct - 1, len(backoff) - 1)]
    yield f"[Info] 上游错误，{d}s 后轮次级重试 ({self._empty_ct}/{max_turn_retries})...\n"
    end = time.time() + d
    while time.time() < end:
        if sess is not None and getattr(sess, 'should_stop', None) and sess.should_stop():
            return StepOutcome({}, should_exit=True)
        time.sleep(0.5)
    return StepOutcome({}, next_prompt=prompt)
```

关键点：

- **可中断睡眠**：500 ms 粒度轮询 `should_stop()`，用户点停止后最迟 0.5 秒退出，不会"停不下来"。
- **返回 `next_prompt=prompt`**：把原始错误提示原样回灌给模型，语义与上游原有设计一致（上游是立刻重发，我们只是先等）。
- **`yield` 进度行**：等待期间界面有可见反馈，不是黑屏几分钟。
- **`_llm_session()` 辅助方法**：`getattr(getattr(self.parent,'llmclient',None),'backend',None)`，parent 缺失时返回 `None` 而不抛异常（测试与降级路径都安全）。

配套的**回归防护（本方案最高风险点）**：`agent_loop.py` 工具分发处，真实工具调用成功时清零计数器：

```python
if tool_name == 'no_tool': pass
else:
    handler._empty_ct = 0  # 真实工具调用 = 模型恢复正常，清零空响应计数
```

漏改此项的后果：计数器跨任务累积，后续一次普通空响应会被误判为"第 N 次失败"导致整轮莫名提前退出。代码里留了注释，测试 T7 直接对该段源码做断言。

### 3.3 R3：Goal Mode 完成驱动

`check()` 在预算判断**之前**插入完成判定：

```python
# 完成驱动：agent 宣告完成即收口，剩余预算不消耗；不足 2 轮视为过早，忽略信号
if state.get('completion_signal'):
    if int(state.get('turns_used', 0) or 0) >= 2:
        state['status'] = 'done_completed'
        state['end_time'] = time.time()
        _save(state)
        return '/exit'
```

**`turns_used >= 2` 的必要性**：第 1 轮唤醒时模型尚未做过任何检验，此时自我宣告"完成"几乎必然是幻觉。要求至少 2 轮，把"创造 → 检验"闭环作为最低门槛。这是本设计对 PRD 的加固，PRD 未明确轮次门槛。

`CONTINUATION_PROMPT` 增补完成协议，并新增 `{state_file}` 占位符（`check()` 用 `STATE_FILE` 格式化传入），让模型知道往哪个文件写：

```
完成协议（当且仅当 objective 已完整达成）：
1. 在 state 文件（{state_file}）写入 "completion_signal": {"verdict": "完成判定", "evidence": "客观证据列表"}
2. 证据必须可验证（测试结果/产物清单/逐条对照原始需求）
虚假完成声明会被后续检验推翻并浪费预算，宁缺毋滥。
未写 completion_signal 就继续按下面的流程推进。
```

原文"完成即停，预算耗尽为保底"保留，与新增协议一致。

## 4. 配置链路（跨语言契约）

```
GUI 模型设置
  → core/src/managed_model_layers.rs   (defaults 层 6 键白名单；overrides 层自由)
  → managed-models.json                (advancedOptions 逐字落盘)
  → runner/managed_runtime.py:170      (cfg.update(advanced))
  → llmcore.BaseSession(cfg)           (读 retry_schedule / turn_retry_max)
```

**结论**：把两个新键写进任一模型的 **advancedOverrides** 即可生效，无需改 Rust、无需改 GUI。写进 **defaults 层**则会被白名单丢弃——这是已知限制，见 §7。

## 6. 回归风险与防护

| 风险 | 防护 |
|---|---|
| 计数器跨任务累积导致提前退出 | `agent_loop.py` 清零 + T7 源码断言 |
| `_retry_or_exit` 改生成器后调用点失效 | 4 个调用点全部改为 `yield from`；`try_call_generator` 原生支持 |
| 用户停止后仍在等待 | 500 ms 轮询 `should_stop()`；T5 断言停止后**零睡眠** |
| 配置写错导致会话起不来 | `_normalize_retry_schedule` 失败即回退默认，不抛异常 |
| 服务端给荒谬 `retry-after` | 保留 `max_retry_after` 上限，超限直接不重试 |
| Goal Mode 首轮幻觉宣告完成 | `turns_used >= 2` 门槛；T9 断言首轮信号被忽略 |
| 等待期间界面无反馈 | `yield` 进度行 `[Info] 上游错误，Ns 后轮次级重试 (n/max)...` |

## 7. 已知限制（未做，需产品决策）

1. **配置界面无入口**：引擎已能读 `retry_schedule` / `turn_retry_max`，但模型设置页没有对应输入控件。用户当前只能通过 `advancedOverrides` 手工写入。若要在 UI 暴露，需改 `core/src/managed_model_layers.rs` 的 `DEFAULT_KEYS` 白名单 + `gui/src/lib/managed-model-layers.ts` 的 `MANAGED_MODEL_DEFAULT_KEYS` + 设置页控件（数组字段需自定义控件）。
2. **`turn_retry_max` 与请求级 `max_retries` 语义不同**：前者是"整轮重发"次数，后者是"单次请求内重试"次数。UI 上若暴露需明确区分。
3. **未做真实 503 端到端注入验证**：单元测试覆盖了退避数值、停止短路、预算边界，但没有可控的 503 上游。端到端验证需在真实故障窗口观察，见验收标准 §4。
